Détection d’arythmies ECG

J’ai préparé les signaux ECG puis entraîné et comparé trois modèles d'intelligence artificielle pour repérer les battements anormaux chez de nouveaux patients.

Problématique

Comment détecter automatiquement les battements ECG anormaux chez des patients dont les données n’ont pas servi à entraîner le modèle ?

Contexte

Un électrocardiogramme enregistre l’activité électrique du cœur. Une arythmie est un trouble du rythme cardiaque. Mon objectif est de repérer les battements anormaux dans ces signaux. Ce projet reste pédagogique et ne constitue pas un dispositif médical.

Ma contribution

J’ai préparé les données puis entraîné et comparé les différents modèles. J’ai construit une évaluation par patient et analysé les erreurs pour comprendre les limites de chaque approche.

Données

J’ai utilisé les annotations de la base MIT-BIH pour regrouper les battements retenus dans une classe normale et une classe anormale.

SourceMIT-BIH Arrhythmia Database sur PhysioNet. La base contient 48 enregistrements de 47 patients. Les signaux sont échantillonnés à 360 Hz.
Battements retenus101 015 battements au total. Ils comprennent 75 022 battements normaux et 25 993 battements anormaux. La classe anormale représente 25,7 % des données.
ClassesLa classe normale correspond à N. La classe anormale regroupe A · V · L · R · F · E · J. Les autres annotations sont exclues.
SegmentChaque battement contient 252 points. Le segment commence 0,25 s avant le pic annoté et se termine 0,45 s après.

Méthode et outils

J’ai comparé une approche par variables calculées à un CNN 1D sur le signal normalisé. J’ai aussi testé l’apport des intervalles RR.

Voir la méthode détaillée

  1. Segmentation des battements

    J’ai segmenté le signal autour des pics fournis dans les annotations. Chaque fenêtre contient 252 points et couvre 0,25 s avant le pic et 0,45 s après. J’ai utilisé ces segments pour étudier la morphologie des battements. Cela correspond à leur forme dans le signal. La détection automatique des pics n’est pas étudiée ici.

  2. Normalisation par Z-score

    J’ai normalisé chaque segment par Z-score avant de l’envoyer au CNN. Cette transformation réduit les différences d’échelle entre les battements. Le modèle peut ainsi comparer leur forme. J’ai conservé le signal brut pour calculer les variables d’amplitude des modèles classiques.

  3. Modèles classiques et CNN 1D

    J’ai entraîné une régression logistique et un Random Forest à partir de variables calculées sur chaque battement. J’ai comparé leurs résultats à ceux d’un CNN 1D. Ce réseau de neurones convolutif apprend à repérer des motifs directement dans les segments normalisés.

    J’ai utilisé la régression logistique comme référence. Le Random Forest m’a aussi permis d’examiner l’importance des variables. J’ai testé une variante sans les intervalles RR pour mesurer l’apport du rythme.

  4. Pondération des classes

    Les battements anormaux représentent 25,7 % des données. J’ai pondéré les classes pendant l’entraînement de chaque modèle pour tenir compte de ce déséquilibre. Les erreurs sur la classe anormale ont ainsi davantage de poids dans l’apprentissage.

  5. Optimisation du seuil de décision

    Le seuil détermine à partir de quel score un battement est considéré comme anormal. J’ai choisi sur le jeu de validation celui qui donne le meilleur score F2. Je l’ai ensuite comparé au seuil habituel de 0,5 pour voir son effet sur le nombre d’anomalies détectées et de fausses alertes.

    Le score F2 donne plus de poids au rappel qu’à la précision. J’ai réglé le seuil sur la validation et gardé le jeu de test pour l’évaluation finale.

Variables morphologiques et intervalles RR

J’ai calculé 17 variables par battement. Les 13 variables morphologiques décrivent notamment l’énergie et l’amplitude du signal. Elles prennent aussi en compte les pentes ainsi que l’aire et la largeur du battement. Les 4 variables de rythme reposent sur les intervalles RR. Un intervalle RR est le temps entre deux pics R successifs. J’ai entraîné une régression logistique et un Random Forest de 300 arbres de décision avec ces variables. J’ai aussi testé le Random Forest avec les seules variables morphologiques.

Architecture du CNN 1D

J’ai construit un CNN 1D sous PyTorch pour analyser les segments normalisés. J’ai utilisé 3 blocs convolutifs de 16 puis 32 puis 64 filtres. L’architecture comprend BatchNorm et un dropout de 0,3. J’ai entraîné le réseau pendant 10 époques. Le modèle ne reçoit aucune variable de rythme.

Protocole d’évaluation

J’ai séparé les données par patient pour tester les modèles sur des personnes absentes de l’entraînement. Les trois ensembles ne contiennent aucun patient en commun.

Entraînement · 25 patients Validation · 7 Test · 15

Le jeu d’entraînement contient 55 821 battements. La validation en contient 13 210 et le test 31 984.

Résultats

J’ai évalué les modèles sur les 15 patients du test. Les scores portent sur la classe anormale. La précision et le rappel ainsi que le score F1 sont calculés avec un seuil de 0,5.

Le rappel indique la part des battements anormaux repérés par le modèle. La précision indique la part de vraies anomalies parmi les battements signalés comme anormaux. La ROC-AUC résume la capacité du modèle à séparer les deux classes sur l’ensemble des seuils.

Ce que j’en conclus

Des ROC-AUC proches avec des compromis différents

J’ai obtenu une ROC-AUC de 0,867 avec le CNN et de 0,864 avec le Random Forest. Ces valeurs sont proches. Le rappel du Random Forest atteint 89,6 % au seuil de 0,5. Celui du CNN est de 71,6 %. Le Random Forest repère donc davantage de battements anormaux.

Le CNN a une meilleure précision avec 55,2 % contre 50,9 %. Il obtient ces résultats sans calculer les variables utilisées par les modèles classiques. Je n’observe pas de modèle meilleur sur tous les critères.

Un apport limité des intervalles RR dans cet essai

J’ai comparé le Random Forest avec et sans les intervalles RR pour isoler leur effet. Leur ajout augmente la ROC-AUC de 0,008 mais réduit la précision moyenne de 0,059. Cette précision moyenne résume la courbe précision-rappel. Elle est différente de la précision au seuil de 0,5 présentée dans le tableau. J’ai aussi examiné l’importance des variables. Les variables de forme restent les plus importantes dans ce modèle.

Le choix du seuil reste fragile

J’ai retenu un seuil de 0,012 pour le Random Forest à partir des 7 patients de validation. J’ai constaté qu’il donne un rappel de 99,99 % sur le test mais une précision de 24,8 %. Presque tous les battements sont alors signalés comme anormaux. Le score F2 passe de 0,778 à 0,623.

Le même réglage améliore le score F2 du CNN. Il passe de 0,676 à 0,750. Le seuil choisi sur un petit groupe de patients ne fonctionne donc pas aussi bien pour tous les modèles sur le test.

Les résultats varient selon les patients

J’ai examiné la répartition des battements anormaux entre les patients du test. Les enregistrements 207 et 214 contiennent presque uniquement des battements anormaux. Ils représentent à eux seuls 54 % des battements anormaux du test. Un autre enregistrement ne contient aucune anomalie. Cette répartition m’a montré que les scores globaux dépendent beaucoup des patients présents dans le test.

Limites et suite

Limites

Je n’ai pas calculé d’intervalles de confiance. La validation repose sur 7 patients seulement. Les modèles distinguent les battements normaux des battements anormaux sans identifier le type d’anomalie.

Pistes

Je pourrais tester plusieurs découpages avec une validation croisée par groupes de patients. Cela permettrait aussi de revoir le choix du seuil. Un bootstrap permettrait d’estimer des intervalles de confiance. Je pourrais ensuite combiner le signal et le rythme dans le CNN ou essayer de reconnaître les différents types d’anomalies.
